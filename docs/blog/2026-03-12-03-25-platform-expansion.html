12.3.-25.3.2026: BusDK laajenee gateway-, inspection- ja AIZ-pintoihin

Maaliskuun puolivälissä 2026 BusDK:n historia osoittaa selvän laajenemisen. Projektin painopiste ei enää ole vain moduulilistassa, testeissä ja trackereissa, vaan myös uusissa käyttöpinnoissa: inspection, gateway, bus-portal ja AIZ tulevat näkyviksi osiksi kokonaisuutta.

Tärkeää on, että laajeneminen tapahtuu kuitenkin BusDK:n alkuperäisen luonteen ehdoilla. Commitit korostavat edelleen pinnausta, portability-fixejä, CLI CRUD -sopimuksia ja deterministisiä release-artifakteja.

Havaintoikkuna: 2026-03-12 ... 2026-03-25Inspection + gateway + AIZTagit v0.0.39 ... v0.0.48

TL;DR

  • SMB: BusDK alkaa näyttää laajemmalta operatiiviselta alustalta kuin yksittäiseltä kirjanpitotyökalulta.
  • Dev: gateway CLI CRUD -sopimukset, inspection-state storage, Windows-portability ja release-assetit tulevat näkyviksi kehitysakseliksi.
  • Saatavuus: tähän vaiheeseen osuvat tagit v0.0.39 ... v0.0.48.
  • Yhteensopivuus: laajeneminen rakentuu moduuleina ja release-scaffoldingina, ei monoliittisena uudelleenkirjoituksena.

Keskeiset tapahtumat

13.3.2026

Portabiliteetti ja ympäristörajojen käsittely näkyvät committeissa

Commit a611e60 päivittää bus-data-moduulin Windows mmap -portabiliteettia varten ja 7ac4511 muuttaa bus-api:a loopback bind -testin skip-käyttäytymisen osalta. Tämä on käytännöllistä järjestelmätyötä, ei markkinointia.

14.3.2026

Nykyisen työtilan comparatives-linja tarkentuu

Commit 35ce9f3 päivittää submoduleja current-workspace comparatives -tukea varten ja 90a0f88 selkeyttää prior-year input -ohjeistusta. BusDK yrittää siis pienentää ympäristöön liittyvää yllätysastetta myös raportointipuolella.

17.3.2026

Inspection ja bus-portal saavat release scaffoldingin

Commit 38c7e5a lisää bus-inspection-submodulen, synteettisen full-2024 compose-tiedoston bus-portal:lle ja release-workflown, joka julkaisee multi-arch GHCR -kuvan. Tämä on yksi historian selkeimmistä laajentumissignaaleista.

21.3.2026 ... 22.3.2026

Gateway muuttuu konkreettiseksi hallintapinnaksi

Commitit e31dc1d, 34e0644, c470130 ja 6817420 seuraavat gatewayn CLI-admin-, CRUD-, shared storage- ja authenticated inspection -päivityksiä. Tämä ei ole enää vain idea modulista vaan sarja eksplisiittisiä sopimuksia.

25.3.2026

AIZ rekisteröidään release-pintaan

Commitit 70a230d, b12d7f9 ja e83a8c0 tuovat AIZ:n mukaan docs- ja release-pintaan. Samalla julkaisuarkkitehtuuria rikastetaan alias-artifakteilla commitissa d871230.

Mitä tämä kertoo BusDK:n suunnasta

Platform-ajattelu on todellista

Inspection-, gateway- ja portal-commitit osoittavat, että BusDK ei jää vain paikallisen CSV-työtilan orkestroijaksi. Se rakentaa laajempaa operatiivista ympäristöä, mutta tekee sen edelleen moduuleina ja release-pinnan kautta.

Laajentuminen ei syrjäytä kuria

Kehittäjälle tärkeä signaali on se, että samaan vaiheeseen osuvat myös portability-fixit, ympäristöskipit ja deterministinen release-paketointi. Kasvu ei tapahdu prosessikurin kustannuksella.

Näin todennat tämän vaiheen

git log --date=short --pretty=format:'%ad %h %s' --since=2026-03-12 --until=2026-03-25
git show --stat --summary --format=medium 38c7e5a
git for-each-ref --sort=creatordate --format='%(creatordate:short) %(refname:short)' refs/tags | tail -n 10

Muutosloki tästä vaiheesta

Added

  • bus-inspection-submodule ja bus-portal-release scaffolding.
  • Gateway CLI CRUD -sopimusten näkyvä seuranta.
  • AIZ release- ja docs-pintaan.

Changed

  • Windows-portabilitya ja ympäristöstä johtuvia testiskippejä käsiteltiin suoraan moduulipinneissä.
  • Comparatives- ja prior-year input -ohjeistus tarkentui.

Compatibility

Tämä vaihe lisää pintoja ja julkaisutapoja, mutta tekee sen edelleen moduulirajojen kautta. Historiassa ei näy yhtä keskitettyä breaking-resettiä, vaan hallittu laajeneminen.
