bus-run toi projektin omat toiminnot, skriptit ja pipelinet .bus/run-hakemistoon

15.2.2026 bus-run Toiminnot Pipelinet

bus-run toi BusDK:hon oman komentopinnan projekteille, jotka haluavat ajaa omia promptteja, skriptejä ja pipelineja ilman että ne sidotaan bus-dev-työnkulkuun. Sisältö löytyy projektin omasta .bus/run-hakemistosta ja ajetaan suoraan nimellä.

Tiiviisti

TL;DR

  • bus-run toi käyttäjän määrittelemät toiminnot, skriptit ja pipelinet yhden komennon alle.
  • Projektikohtainen sisältö luetaan .bus/run-hakemistosta eikä sitä tarvitse kovakoodata erillisiin shell-kääreisiin.
  • bus run list näyttää, mitä projektissa on tarjolla, ja komento voidaan ajaa suoraan nimellä.
  • Tämä erottaa yleisen ajopinnan bus-dev-moduulin kehitystyönkuluista.

Muutoksen ydin on, että projektin oma automaatio tuli näkyväksi Bus-komentona. Jos projektin juuressa on esimerkiksi yksinkertainen skripti .bus/run/check.sh, bus-run osaa sekä näyttää sen että ajaa sen ilman erillistä käynnistysskriptiä. 

.bus/run/check.sh
#!/usr/bin/env sh
printf 'script ok\n'

bus-run list
bus-run check
check	action script	.bus/run/check.sh
script ok

Ensimmäinen komento kertoo, että projektissa on yksi ajettava token nimeltä check ja että sen lähteenä on skripti .bus/run/check.sh. Toinen komento näyttää, että toiminto voidaan ajaa suoraan nimellä ja että sen tuloste tulee sellaisenaan ulos. Käytännössä tämä tekee projektin omasta automaatiosta paljon helpommin löydettävää: sama pinta näyttää sekä mitä on tarjolla että miten se käynnistetään.

Samalla raja bus-dev:n ja bus-run:in välillä selkeytyi. bus-dev jäi kehitystyönkuluille kuten plan, work ja e2e, kun taas bus-run keskittyy projektin omaan suoritettavaan sisältöön: promptteihin, pipelineihin ja skripteihin. Tämä on tärkeä ero, koska kaikki ajettava ei ole kehitystyökalua eikä kaiken tarvitse kulkea saman workflow-sopimuksen läpi. Komentopinnan nykyinen sopimus löytyy bus-run-dokumentaatiosta.
