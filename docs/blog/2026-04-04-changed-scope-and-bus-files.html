changed-scope huomaa muuttuneet submoduulit ja bus files tuo tiedostotarkistukset

Root-tason changed-scope-korjaus paransi sitä, mihin testeihin muutokset kohdistuvat. Samalla bus files toi uuden komentopinnan paikallisten tiedostojen ja raporttiartefaktien tarkistamiseen.

4.4.2026 changed-scope bus-files

Tiiviisti

TL;DR

  • Merkitys: testit kohdistuvat luotettavammin silloin, kun muutos on submodulessa.
  • Uusi pinta: bus files osaa tarkistaa tiedostojen olemassaolon ja raporttirivejä ilman shell-putkia.
  • Vaikutus: sekä sisäinen iterointi että raporttiartefaktien tarkistus selkiytyivät.

Uusi tiedostopinta tekee muutoksen näkyväksi myös loppukäyttäjälle. Sen sijaan että raportin olemassaoloa tai CSV-riviä tarkistetaan erillisillä shell-työkaluilla, saman voi tehdä suoraan Bus-komennolla: 

bus files assert \
  exists \
  examples/synthetic-full-fictional-2024/data-monthly-transfer/tuloslaskelma-2024.pdf

bus files assert row \
  examples/synthetic-full-fictional-2024/data-monthly-transfer/trial-balance-2024.csv \
  --filter code=3000
assertion  target  expected  observed  status
exists     .../tuloslaskelma-2024.pdf  exists  exists  ok

assertion  target  expected  observed  status
row        .../trial-balance-2024.csv  filters=code=3000; rows=>=1  matched_rows=1  ok

Samaan aikaan changed-scope-korjaus varmisti, että root-tason testiajo huomaa myös muuttuneet submodulet eikä oleta kaiken näkyvän vain gitlink-muutoksina superprojektissa. Yhdessä nämä muutokset kiristivät sekä kehittäjän että käyttäjän näkökulmasta samaa asiaa: jos työtilassa tai raporttiartefaktissa tapahtuu olennainen muutos, se pitää havaita oikein.
