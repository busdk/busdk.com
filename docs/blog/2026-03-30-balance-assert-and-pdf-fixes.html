balance assert tuli komentopintaan ja PDF-raportteja korjattiin

bus journal balance assert toi tilisaldojen tarkistuksen suoraan komentopintaan, ja samalla PDF-raportoinnin regressioita korjattiin näkyvästi.

BusDK lisäsi uuden tarkistuspinnan ja stabiloi samalla evidenssi- ja raportointitulosteita.

30.3.2026balance assertPDF regressions

Tiiviisti

TL;DR

  • Merkitys: raportoinnin luotettavuus parani, kun PDF-bugeja käsiteltiin näkyvästi ja assert-ajattelua tuotiin komentopintaan.
  • Toteutus: balance assert ankkuroi verifioinnin CLI:hin sen sijaan, että tarkistus jäisi ulkoiseksi rutiiniksi.
  • Yhteensopivuus: uusi assert-pinta täydensi olemassa olevaa mallia eikä korvannut sitä.

Muutos näkyi yhtä aikaa komentorivillä ja raporteissa. Uusi tarkistuskomento oli esimerkiksi tällainen:

bus journal balance assert \
  1910 \
  2026-03-31 \
  1240.55

bus journal assert \
  match count 1999 \
  --unsettled \
  --older-than 7d \
  --as-of 2026-01-31 \
  0
measure	scope	expected	observed	status
balance	account=1910 as_of=2026-03-31	1240.55	1240.55	pass
match-count	match=1999 unsettled older-than=7d as-of=2026-01-31	0	0	pass

Ensimmäinen tarkistaa tilin saldon suoraan. Toisessa match count on varsinainen tarkistusmuoto, 1999 on valittava kohde, liput rajaavat tarkastuksen ja viimeinen 0 on odotettu rivimäärä. Koska kyse on assert-komennosta, onnistunut tarkistus palauttaa exit-statuksen 0 ja poikkeava tulos virheen. Tarkemmat muodot löytyvät bus journal -dokumentaatiosta.

Samaan aikaan PDF-raportoinnista korjattiin muun muassa comparative source-, later-page annotation-, ledger pagination- ja row text -ongelmia. Lukijalle näkyvä lopputulos oli yksinkertainen: tarkistuksia pystyi ajamaan komentoriviltä, ja raportit näyttivät aiempaa vakaammilta.
