bus-dev toi kehitystyönkuluille yhden yhteisen komentopinnan

11.2.2026 bus-dev Työnkulut Orkestrointi

BusDK sai oman bus-dev-moduulin, joka kokosi kehitystyönkulun vaiheet yhden julkisen komentopinnan alle. Muutos ei jäänyt teoriaksi, vaan rootin orkestrointiskriptit alkoivat heti käyttää samoja bus dev -komentoja modulikohtaisten omien skriptien sijaan.

Tiiviisti

TL;DR

  • bus-dev toi työvaiheet kuten plan, work, e2e, stage ja commit yhden komennon alle.
  • Rootin orkestrointi alkoi kutsua bus dev work- ja bus dev commit -komentoja erillisten modulikohtaisten skriptien sijaan.
  • Pipelinet tekivät toistuvista askelketjuista näkyviä ja ennustettavia.
  • Tämä muutti kehitystyönkulun julkiseksi Bus-pinnaksi samalla tavalla kuin muutkin moduulikomennot.

Ennen tätä muutosta sama työ saattoi olla ripoteltuna useisiin repo- tai modulikohtaisiin skripteihin. bus-dev muutti tilanteen tuomalla kehittäjälle näkyvän komentopinnan, jossa tärkeimmät vaiheet löytyvät yhdestä paikasta. Se näkyy heti myös helpissä: 

bus-dev --help
Operations:
  init
  commit
  plan
  work
  spec
  e2e
  triage
  stage
  retry
  each

Oleellinen muutos ei ollut pelkkä uusi binääri, vaan se että työvaiheille tuli yhteinen sanasto. Kun rootin skriptit siirtyivät kutsumaan bus dev commit ja bus dev work -komentoja, sama pinta alkoi ohjata sekä moduulissa käsin tehtävää työtä että superprojektin orkestrointia. Silloin käyttäjän ei enää tarvitse tietää, onko jokin vaihe piilotettu scripts/-hakemistoon vai toteutettu komentopinnan osana.

Pipelinet tekevät tästä vielä konkreettisempaa. Esimerkiksi sisäänrakennettu round-ketju kertoo yhdellä komennolla, mitä seuraavaksi oikeasti tapahtuu: 

bus-dev pipeline preview round
work
e2e
stage
commit

Tuo on merkittävä parannus verrattuna tilanteeseen, jossa sama työnkulku olisi pitänyt päätellä useasta erillisestä shell-skriptistä. Nyt ketju näkyy eksplisiittisesti: ensin tehdään työ, sitten ajetaan e2e, sen jälkeen valmistellaan staging ja lopuksi commitoidaan. Jos haluat nähdä koko komentopinnan ja pipelinejen nykyisen sopimuksen, jatka bus-dev-dokumentaatioon.
