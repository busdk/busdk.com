BusDK Update

API, agentti, preferences ja sheets tulivat mukaan

Paikallinen API, agentti-integraatio ja taulukkomuotoinen käyttöliittymä tulivat näkyviin oikeina moduuleina ja komentoina.

BusDK ei ollut enää vain taustalla ajettava CLI-runko, vaan myös rajapinta ja selainkäyttöliittymä alkoivat näkyä samassa kokonaisuudessa.

13.2.2026bus-apibus-agentbus-sheets

Tiiviisti

TL;DR

  • Merkitys: BusDK ei ollut enää vain taustarunko, vaan alkoi saada myös käyttöliittymä- ja integraatiopintoja.
  • Toteutus: moduulien määrä ja suunta kasvoivat kerralla merkittävästi, samalla kun submodule-skriptit yhtenäistettiin bus dev -vetoisiksi.
  • Saatavuus: samalle päivälle osuvat tagit v0.0.16 ... v0.0.18.

Muutos näkyi heti oikeina komentoina eikä vain uusina moduuliniminä:

bus api serve \
  --port 8080 \
  --token-bytes 32

bus sheets \
  -C ./workspace \
  serve \
  --enable-agent \
  --port 8092
bus api serve
  -> http://127.0.0.1:8080

bus sheets serve
  -> http://127.0.0.1:8092

Ensimmäinen komento avaa paikallisen rajapinnan workspaceen. Toinen avaa saman workspaceen taulukkomuotoisen käyttöliittymän ja agenttipaneelin. Käytännössä BusDK sai samalla kertaa sekä ohjelmallisen että selainpohjaisen käyttöpinnan. Jos haluat tarkemman sopimuksen komentojen käytöstä, jatka bus api -dokumentaatioon tai bus sheets -dokumentaatioon.

Samalla superprojekti sai uudet moduulit ja submodule-skriptit siivottiin dynaamiseksi bus-*-löydöksi sekä yhtenäisemmäksi bus dev-pinnaksi. Pelkkä moduulien lisääminen ei olisi ollut yhtä hyödyllistä ilman, että niitä pystyy hallitsemaan yhdenmukaisesti. Julkisessa moduuli-indeksissä tämä näkyi heti uusina agentti-, API- ja sheets-merkintöinä.
