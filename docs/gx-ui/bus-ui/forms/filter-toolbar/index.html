Bus UI Filter Toolbar

One compact form for filtering and reset actions.

Use the filter toolbar when a list or report needs a labeled filter strip with submit and reset controls, but the module still owns the actual filtering logic. The toolbar composes field nodes first and only falls back to compatibility HTML when a caller already owns trusted fragments.

Validated surface

FunctionProps typeImport path
FilterToolbarCheckedFilterToolbarPropsgithub.com/busdk/bus-ui/pkg/uikit

When to use it

Use FilterToolbarChecked when a data view needs a set of fields plus submit and reset controls that belong to the owning module. The toolbar is still on pkg/uikit for now. Fields is the preferred composition path; BodyHTML is compatibility only.

See also Field, Submit control, Form, and Reference.

Example

import (
  gx "github.com/busdk/bus-gx/pkg/gx"
  uikit "github.com/busdk/bus-ui/pkg/uikit"
)

toolbarHTML, err := uikit.FilterToolbarChecked(uikit.FilterToolbarProps{
  SourceID: "ledger-filters",
  Fields: []uikit.FieldProps{
    {
      Label:       "Search",
      ControlID:   "search",
      ControlName: "search",
      RenderControlNode: func(attrs map[string]string) (gx.Node, error) {
        return uikit.TextInputNodeChecked(uikit.TextInputProps{
          Name:  "search",
          Attrs: attrs,
        })
      },
    },
  },
})
if err != nil {
  return err
}
