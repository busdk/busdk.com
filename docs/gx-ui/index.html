Write components with Go and markup

A .gx file is a Go package file with markup inside Go functions. Typed props, ordinary control flow, children, safe intrinsic elements, and callback functions all stay visible in the same source package as the presenter.

Start with GX authoring

Notice.gx
type NoticeProps struct {
  Title    string
  Tone     string `gx:",optional"`
  Children []gx.Node
}

func Notice(props NoticeProps) gx.Node {
  return <section class={"notice " + props.Tone}>
    <h2>{props.Title}</h2>
    {props.Children}
  </section>
}

Add interactivity wherever the host needs it

Event callbacks are typed Go functions. Action and resource helpers turn UI events into public result shapes, validated provider requests, field errors, navigation results, or no-op updates without putting credentials into markup.

Learn action and resource dispatch

actions.go
actions := uikit.ActionSet[string]{
  "files.refresh": {
    Token: "files.refresh",
    RunResult: func(moduleID string) uikit.Result {
      return uikit.Success(map[string]string{
        "module": moduleID,
      })
    },
  },
}

state := uikit.NewActionState()
result := uikit.RunAction(actions, state, "files.refresh", "accounting")

Keep product policy in Go

Bus UI handles reusable presentation contracts. Product modules still own data loading, provider calls, authorization, upload policy, evidence access, redaction, billing, usage, and state transitions.
