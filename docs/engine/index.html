Bus Engine

Linux runtime environments for servers and virtualization.

Bus Engine gives teams one product line for Linux-backed runtime environments: local and cloud VMs, verified artifacts, runtime lifecycle control, and Engine OS image building when the environment needs a custom operating-system baseline.

Review Engine OS View modules Discuss deployment

What it is

Bus Engine is the product line for running Bus-controlled Linux environments. Its first surfaces are intentionally small: start the default Engine VM, stop it, inspect health, and open SSH access when an operator needs to debug the runtime.

Engine OS belongs inside this line. It is the custom Linux distribution builder and update workflow for teams that need tighter control over the image, kernel, packages, diagnostics, and artifact provenance used by Engine runtimes.

What it is for

Local Linux runtime

Run a Linux VM through QEMU on developer machines and constrained virtualization hosts.

Cloud VM abstraction

Keep runtime lifecycle behavior above provider-specific VM integrations.

Verified artifacts

Download, mirror, verify, and reuse large images and kernel packages without storing them in Git.

Custom Engine OS

Build and update minimal Linux environments for server and virtualized workloads.

How it fits with Bus Engine

Bus Engine owns the runtime product. Engine OS is the operating-system build and update capability inside that product. This keeps the user-facing line simple: teams choose Bus Engine when they need a controlled Linux environment, then use the default image or an Engine OS image depending on how much OS control they need.

The everyday workflow

bus engine status
bus engine start
bus engine ssh
bus engine stop

The default Engine path starts with an existing verified image and a small runtime lifecycle. Engine OS extends that product line when the team needs to own the Linux build itself: source manifests, staged packages, root filesystem assembly, kernel images, boot tests, and update promotion.
