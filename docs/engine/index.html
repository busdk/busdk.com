Bus Engine Founding Technical Preview

A limited early release for source-access server operators.

Bus Engine Founding Technical Preview is a limited paid early release for operators who want to evaluate Bus Engine before version 1.0. It includes Bus Engine, BusDK, and explicitly listed Engine-related source modules under FSL, official Bus Linux builds, updates, and best-effort technical support. It is for labs, development environments, staging systems, and non-critical workloads.

What the preview is for

The preview is for experienced operators who can inspect source, provide reproducible reports, attach diagnostic bundles, and help shape the platform before the broader beta. Commercial evaluation is allowed, but the preview does not include a production uptime or emergency-response SLA.

Source-access preview

Bus Engine source, BusDK source, and named Engine modules are included under FSL.

Unlimited test systems

One named operator may evaluate the preview across unlimited lab and staging systems.

No binary-only plan yet

The lower-cost binary-only Runtime plan starts later, after source customers test updates and recovery.

One reliable workflow first

The first preview concentrates on one complete system-change workflow: install Bus Linux, configure an AI provider, ask Bus Engine for a system change, inspect the proposed change, approve it, apply it, verify it, and roll it back. AI-controlled server changes use an explicit approval loop by default. 

bus engine status
bus engine start

The change workflow is plan, diff, explicit approval, apply, validate, and rollback. The preview should not silently allow an AI agent to make unrestricted root-level changes.

Build the Bus Linux distribution

Bus Engine OS is the Bus-built Linux distribution managed by AI agents. Its profiles describe the selected runtime image, kernel package, package artifacts, patches, build definitions, and validation steps. Debian cloud images are swappable runtime image artifacts for preview and compatibility work, not the definition of Bus Engine OS itself. 

DEBIAN_IMAGE=./debian-12-genericcloud-amd64.qcow2
DEBIAN_DIGEST="sha256:<digest>"

bus artifacts catalog set debian-cloud-generic-amd64 \
  --handle "$DEBIAN_IMAGE" \
  --digest "$DEBIAN_DIGEST"

KERNEL_DEB=./linux-image-7.1.0_6_amd64.deb
KERNEL_DIGEST="sha256:<digest>"

bus artifacts catalog set bus-engine-kernel-amd64 \
  --handle "$KERNEL_DEB" \
  --digest "$KERNEL_DIGEST"

The catalog command records artifact handles and digests in the configured Bus artifacts catalog. Engine start then asks the artifact integration to fetch and verify the selected runtime image, kernel, and package artifacts before boot.

A profile can use a verified Debian cloud image while the preview hardens installation, updates, recovery, and rollback. The same profile model also selects Bus Engine OS images and Bus-built package sets, so the distribution can move from an interchangeable runtime image toward a fully Bus-controlled Linux release without changing the customer-facing workflow.

AI access is separate

Bus Engine pricing does not include AI credits or OpenAI access. Customers need their own OpenAI Codex subscription or API access for Codex-powered maintenance work. Local AI model use depends on configured Bus LLM and Ollama integrations. Build, boot, checksum, and test steps remain deterministic where the task can be made deterministic.

Preview support boundary

The preview uses one officially supported architecture and a narrow virtualization or hardware matrix. Interfaces, configuration formats, package selections, and upgrade behavior may change before version 1.0. Release versions use pre-release identifiers such as 0.1.0-preview.1.
