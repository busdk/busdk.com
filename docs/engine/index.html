Bus Engine

A Linux distribution you can run and modify with AI agents.

Bus Engine Operating System is a Linux distribution that can be customized from source and maintained with Codex AI agents. It gives teams a managed Linux runtime for Bus workloads, including Linux virtualization on macOS and Windows hosts. The current bus engine surface starts, stops, inspects, and opens operator SSH access to that managed Linux system.

What Bus Engine is used for

Bus Engine is the operating-system layer for Bus environments. It is used to run a controlled Linux server system inside supported virtualization, then change the system through versioned artifacts and source-level maintenance instead of treating the VM as an opaque appliance.

Virtual Linux runtime

Run Linux workloads through Bus on supported Linux, macOS, and Windows hosts.

Configurable distribution

Select the base image, kernel package, OS profile, and component versions.

AI-assisted maintenance

Use Codex agents to adapt source configuration, diagnose boots, and maintain updates.

Run the virtual service

The normal user surface is intentionally small. Start the managed Engine, wait for it to report running, open SSH when operator access is enabled, and stop it when the virtual Linux service is no longer needed. 

bus engine status
bus engine start
bus engine status
bus engine ssh
bus engine stop

A healthy start returns an accepted start action, then status moves toward running. When SSH is available, bus engine ssh returns the operator SSH command for the local Engine port.

Choose the operating-system pieces

Engine profiles resolve their operating-system pieces through the artifacts service. The default profile uses a Debian 12 generic cloud image and a bus-engine-kernel-amd64 kernel package. The same artifact boundary is used for custom kernels and Bus Engine OS images when those profiles are selected. 

DEBIAN_IMAGE=./debian-12-genericcloud-amd64.qcow2
DEBIAN_DIGEST="sha256:<digest>"

bus artifacts catalog set debian-cloud-generic-amd64 \
  --handle "$DEBIAN_IMAGE" \
  --digest "$DEBIAN_DIGEST"

KERNEL_DEB=./linux-image-7.1.0_6_amd64.deb
KERNEL_DIGEST="sha256:<digest>"

bus artifacts catalog set bus-engine-kernel-amd64 \
  --handle "$KERNEL_DEB" \
  --digest "$KERNEL_DIGEST"

The catalog command records the artifact handle and digest in the configured Bus artifacts catalog. Engine start then asks the artifact integration to fetch and verify the selected artifacts before VM boot.

The base system can come from a verified Debian cloud image or from a Bus Engine OS image artifact. Component versions are represented by the selected image, kernel package, package artifacts, and profile metadata, so each Engine profile can be pinned, tested, and updated independently.

AI access is separate

Bus Engine pricing does not include AI credits or OpenAI access. Customers need their own OpenAI Codex subscription or API access for Codex-powered maintenance work. Local AI model use depends on configured Bus LLM and Ollama integrations. Build, boot, checksum, and test steps remain deterministic where the task can be made deterministic.

Supported targets now

Bus Engine runs Linux workloads through Bus-supported virtualization providers, including supported macOS and Windows host configurations. Customer-defined physical servers, boards, appliances, and embedded devices can be explored with Bus Engine, but hardware-specific enablement and certification require separate engineering and validation work.
