Bus Engine

The modules behind the Engine product line.

Bus Engine is one product line for Linux runtime environments. The implementation keeps runtime control, Engine OS composition, artifact storage, API access, and provider-specific virtualization in separate ownership boundaries.

Update path

OS updates should be treated as artifact and policy changes, not ad hoc machine mutation. The long-term path connects Bus Engine OS package/image outputs to Bus update infrastructure so environments can receive verified kernel, rootfs, and image updates with provenance and rollback planning.

Why the split matters

Engine is the product line, not one module. The OS builder should not become the runtime controller, and the runtime controller should not become a package manager. Keeping these boundaries clear makes the product easier to test: package archives can be validated without starting a VM, QEMU can boot-test an image without knowing how every package was built, and artifact mirrors can verify checksums without knowing the workload.
