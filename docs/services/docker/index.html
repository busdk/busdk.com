Bus Services

Use Bus Services inside a Docker image.

In a container, Bus Services should be the foreground supervisor for Bus processes. Bake the public stack and profiles into the image, mount writable state and logs, inject secrets at runtime, and use JSON status as the health check.

Runtime shape

  • Install Bus release binaries in the image, including bus, bus-services, and bus-integration-services.
  • Copy services.yml to /opt/bus/services.yml.
  • Copy the profile tree to /opt/bus/profiles.
  • Mount /var/lib/bus and /var/log/bus as writable runtime locations.
  • Provide secrets such as BUS_EVENTS_JWT_SECRET at runtime, not in the image layer.

Entrypoint command

/usr/local/bin/bus services up \
  --file /opt/bus/services.yml \
  --profile-dir /opt/bus/profiles \
  --state-dir /var/lib/bus/services \
  --foreground \
  --all

--foreground keeps the Services supervisor attached to the container lifecycle. --state-dir keeps frozen config, status files, token files, and logs out of the read-only stack location.

Dockerfile skeleton

FROM ubuntu:24.04

ARG BUS_RELEASE_TARBALL
ARG BUS_RELEASE_SHA256

RUN apt-get update \
  && apt-get install -y --no-install-recommends ca-certificates postgresql-client \
  && rm -rf /var/lib/apt/lists/*

COPY ${BUS_RELEASE_TARBALL} /tmp/busdk.tgz
RUN echo "${BUS_RELEASE_SHA256}  /tmp/busdk.tgz" | sha256sum -c - \
  && tar -xzf /tmp/busdk.tgz -C /usr/local/bin \
  && rm /tmp/busdk.tgz

COPY services.yml /opt/bus/services.yml
COPY profiles /opt/bus/profiles

VOLUME ["/var/lib/bus", "/var/log/bus"]
ENTRYPOINT ["/usr/local/bin/bus", "services", "up", "--file", "/opt/bus/services.yml", "--profile-dir", "/opt/bus/profiles", "--state-dir", "/var/lib/bus/services", "--foreground", "--all"]

Production images should pin the Ubuntu base image and verify the Bus release artifact checksum or signature. Worker-capable images may add Go, Git, SSH, and runner tools, but project source and task worktrees should be mounted or created at runtime instead of baked into the image.

Compose health check

healthcheck:
  test:
    - CMD
    - /usr/local/bin/bus
    - services
    - ps
    - --file
    - /opt/bus/services.yml
    - --profile-dir
    - /opt/bus/profiles
    - --state-dir
    - /var/lib/bus/services
    - --format
    - json
  interval: 10s
  timeout: 5s
  retries: 6

JSON status exits non-zero when the expected stack is degraded, while still writing the status payload. That gives Docker a real health signal and gives operators the same non-secret status output for troubleshooting.

Dependency containers

A single Bus runtime container does not have to contain every standard dependency. PostgreSQL and Mailhog can run as ordinary Compose services when that is the clearer local-development or customer-controlled deployment shape. The important boundary is that Bus-related services remain supervised by Bus Services and that dependency connection details are explicit runtime configuration.
