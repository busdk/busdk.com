Bus Services

Run the service stack your product depends on.

Bus Services gives a BusDK project one repeatable control surface for the long-running pieces around it: databases, Events APIs, worker runtimes, task services, repositories, product APIs, relays, and future provider-backed services.

Start a stack Use Docker Discuss deployment

What it is

A service is something Bus can create, start, stop, observe, or verify. Bus Services reads a public services.yml file, resolves the referenced profiles, validates non-secret configuration, starts services in dependency order, and records status under a Services state directory.

The same stack can be used by a developer on a laptop, by a CI smoke test, by a dedicated customer environment, or by a Docker image where Bus Services is the foreground supervisor for Bus processes.

What it is for

Local product stacks

Start the database, Events API, task service, worker service, repos service, API, and relay needed by a BusDK product checkout.

Repeatable operations

Replace ad hoc setup notes with a stack file, a status command, log paths, and predictable shutdown behavior.

Deployment packaging

Copy a stack and profiles into an image or dedicated host and run one Bus command as the service supervisor.

Supportable customer environments

Give operators a common way to inspect what is running without exposing secrets, DSNs, or private token values.

The everyday workflow

bus services stack validate --file services.yml --profile-dir profiles --all
bus services stack plan --file services.yml --profile-dir profiles --all --format json
bus services up --file services.yml --profile-dir profiles --all
bus services ps --format json
bus services down

Validation catches stack and profile errors before startup. Planning shows the non-secret service plan. Startup freezes the resolved config so shutdown still targets the running stack even if the source file changes later.
